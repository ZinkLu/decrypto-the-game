# Teammate Decoding — 队友解码

> 页面组件: `TeammateDecoding.tsx`
> 游戏阶段: `decrypt`
> 角色: `teammate`（加密者的队友）

## 页面用途

队友根据加密者给出的 3 条线索，猜测每条线索对应的密码序号（1-4）。这是解码阶段的核心交互。

## 页面信息

- **倒计时** — 90 秒限时，带进度条
- **密码词参考板** — 始终显示本队 4 个密码词（编号 1-4），类似软木板上钉着的卡片
  - 选中某个编号时，对应密码词卡片高亮
- **答案行** — 3 行（每条线索一行），每行显示：
  - 线索编号
  - 线索内容
  - 答案输入格（点击激活）
  - 状态指示（空 / 已填 / 提交后的对错结果）
- **数字键盘** — 1-4 四个按钮，点击填入当前激活的答案格

## 用户操作

1. **点击答案格** — 激活某一行的输入
2. **点击数字键** — 将 1-4 填入当前激活的答案格
   - 填入后自动跳到下一个空格
   - 键盘数字键 1-4 同样有效（桌面端快捷方式）
3. **清除答案** — 点击已填写的答案格可清空并重新填写
4. **提交解码** — 3 格全部填满后出现「提交解码」按钮，点击提交

## 用户流程

```
看到 3 条线索 + 4 个密码词参考
→ 点击答案格 1 → 选择数字（密码词编号）
→ 自动跳到答案格 2 → 选择数字
→ 自动跳到答案格 3 → 选择数字
→ 出现提交按钮 → 点击提交
→ 等待判定结果（显示每行对错）
```

## 提交后反馈

提交后显示「等待判定…」，约 1.5 秒后每行显示 ✓ 或 ✗ 及正确答案。

## 状态流转

- 前置: `phase_change` 消息中 `phase=decrypt` 且 `your_role=teammate`
- 后续: 判定完成后进入 **RoundResult（回合结算）** 或 **InterceptedWaiting（被拦截等待）**

## Store 交互

- 读取: `myWords`, `clues`
- 写入: `submitDecrypt(guess[3])`
