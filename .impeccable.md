## Design Context

The full design description is in `docs/console/README.md` and the documents it links to. This file is the short form for design tools.

### Users
Chinese- and English-speaking Encrypto players creating rooms and playing with friends or AI. Desktop first; phones get a compact terminal without the 3D machine.

### Brand Personality
Tactile, playful, a little mysterious. A light-hearted party game, not a military instrument.

### Aesthetic Direction
One modeled electronic console in warm ivory, charcoal and red, built with Three.js. The original board game is a reference for layout and colour only (a machine-like screen, four numbered red windows). Its props are not copied: every prop becomes the electronic device a console of that era would use for the job. Keyword windows are LED dot-matrix modules, the secret code arrives on a floppy disk, scores are bistable mechanical flags, the record is printed on a paper tape. No cards, film or tokens.

Every neutral finish shares the ivory's warm undertone (OKLCH hue about 68–82 with grey-level chroma). Lamps, displays, the red parts and the theme team colours keep their own hues.

### Design Principles
- One machine carries everything. The main CRT presents one task at a time; the surrounding hardware carries room, teams, score, time and history.
- Functions of the machine live on modeled controls, never on invisible hot zones. The red ACTION key is the single confirmation.
- Session settings (language, theme, graphics quality) are plain page UI outside the machine.
- Motion comes from small simulations (tube electronics, a sheet torn by a hand, a beam on phosphor), not from authored easing curves.
- Instruments start from the real principle, every knob reshapes the picture steplessly and at once, and play wins over rigour.
- Fixed chassis legends are English and never change. Active displays, roster cards, phase indicators and receipts are bilingual; names and submitted clues keep their original text. Both languages use the same base type sizes; long keywords wrap and are never truncated.
- Private information appears only where it belongs and is withdrawn at once when the seat, the link or the key disk changes.
- Every control is a real DOM element: keyboard, screen reader and the system input method work. Reduced motion settles every action at once. Without WebGL the page falls back to text controls.
- Cover every role and phase, including disconnected, powered-off and error states.
