# Console 背面接口联动设计

日期：2026-09-22

状态：已实施运行时联动，复用现有模型。供电、AUX、脱机与恢复共用硬件状态推导，并有自动化测试。

## 设计判断

把背面定义为这台机器的连接与供电面。玩家在这里改变设备条件，正面的屏幕、灯和仪表自然响应。

实施前已有完整的硬件造型、拔插动作、柔性线缆、电池仓和反馈机制；主要缺口是动作没有后果。此前拔插只修改 `unpluggedCables` / `removedBatteries`，提示为“仅为机械演示”。本次保留这些机构，将它们接入统一硬件状态。

目标用户沿用项目设计背景：与朋友或 AI 玩 Decrypto 的中英文玩家。联动保持触感、神秘感和桌面设备的可信度，默认接线完整、开机即可使用。探索背面始终是可选行为。

## 三条明确的关系

| 背面部件 | 职责 | 正面联动 | 恢复 |
| --- | --- | --- | --- |
| DC 电源 + 四节电池 | 整机供电 | 屏幕、灯、SIGNAL、示波器、读盘和电动走纸 | 有电源且总开关在 ON 时恢复 |
| LINK / RJ45 | 终端通信 | NETWORK 灯、主屏通信状态、游戏指令提交 | 插回后重新呈现当前对局 |
| AUX / SERIAL | 外接接收机的信号遥测 | SIGNAL 指针、AUTO / MAN 调谐反馈 | 插回后恢复当前调谐与增益对应的信号 |

串口这里承载的是虚构外接接收机的遥测数据；这是新增的设备设定，不表示当前已有外设或真实串口通信。

示波器保留现有 INPUT—CAL OUT 本地校准回路。它由整机供电，FREQ / WAVE / TIME/DIV / X-Y 的含义保持一致；网线和 AUX 拔出都不让本地波形消失。LOCK 仍只表达振荡器锁定程度。

软盘保留密钥载体的职责。读盘取决于供电、盘的位置和本轮权限，不取决于 AUX；断网不会机械弹盘，断电也不会自动把盘推出。

## 1. 供电：最完整的一条发现路径

供电优先级：外部 DC → 完整电池组 → 无供电。四节电池作为一组，缺任何一节都不能接管供电；打开仓盖本身不影响供电。

| 条件 | 结果 |
| --- | --- |
| DC 已连接 | 外部供电；取出电池不影响机器 |
| DC 已拔出，四节电池齐全 | 电池供电；设备继续正常使用 |
| DC 已拔出，任一电池缺失 | 整机失电 |
| 总开关 OFF | 终端关闭；重新插电也不会擅自开机 |

拔掉 DC 且电池完整时，背面立即出现“已切换电池供电”；指示灯保持稳定。可用一次轻微继电器声确认切换，服从现有声音总开关。无需屏幕变暗、制造画面故障或重启，电池供电应当是可靠的。

电池接管时，CRT 右上角显示紧凑的细线电池外框与小电极，内部为四格倾斜平行四边形，三格亮、一格暗，旁边显示 `75%`。整体保持扁平。当前电量为固定演示值，不模拟消耗；接回 DC 或失电后隐藏。断网页面保留电量提示，手机端与文字回退同步显示。

随后取出一节电池时，背面灯熄灭，提示“终端无供电 · 接回 DC 或装齐电池”。正面复用已有 CRT 关机、点阵熄灭和指针归位效果。机械计分旗、纸张和磁盘保留物理位置。

恢复任一可用电源后，若总开关仍为 ON，正常启动并呈现当前状态。若仍为 OFF，提示“供电已恢复 · 电源开关仍关闭”。

不引入电量消耗、充电、随机接触不良或维护任务。

## 2. 网线：终端脱机，房间会话保留

拔出网线代表这台终端进入本地状态。底层房间会话继续接收状态，以保留玩家席位和恢复能力；对局和其他玩家继续进行。

### 拔出

- 接触分离时，背面 RJ45 的 LINK / ACT 灯停止，正面 NETWORK 灯熄灭。
- 主屏进入“已断开连接”页，区分网线拔出与真实网络重连。四个词窗统一显示“离线”，房间码显示 `0000` 并停用复制。真实房间码、秘密词与草稿保留在会话中，重连后按当前权限恢复；手机与文字回退界面保持一致。
- 暂停从此终端发出创建、加入、换队、开始、提交等游戏指令；输入与本地笔记可保留，不能出现“提交成功”的反馈。
- 软盘机构仍响应供电和当前权限，断线页面不显示私密密码；本地示波器、SIGNAL、声音设置仍可使用。
- 公开纸带历史仍可查阅。实时阶段、计时及计分更新在本地状态下停止呈现，并明确标记；返回在线状态直接追上当前进度。
- 机身外已有的回合提醒继续显示当前阶段及“对局仍在进行”，作为玩家恢复的依据，不伪装为来自断线终端的画面。

### 插回

- 连接到位后做一次短暂接通反馈；恢复输入与显示不额外等待装饰动画。
- 当前服务器连接可用且最新状态有效，才让 NETWORK 稳定亮起。
- 若真实网络仍不可用，显示“接线已恢复 · 正在重连”，区分物理接线和真实连接。
- 直接回到当前回合和当前角色，不按顺序回放错过的提交、声音或打印动画。
- 不自动提交断线期间的输入。原回合仍可操作时恢复草稿；已过期则保留为旧草稿，不填入新回合。

已发出而尚未确认的提交，以服务器回执为准；拔线不能撤回指令，也不能触发重发。

这条关系会临时阻止自己的游戏操作，必须有清楚的恢复入口：前面主屏的脱机说明旁，仅在需要时显示“接回网线”；可直接恢复对应插头。无供电时同类入口放在机身外已有状态提示中，显示“接回电源”。这些入口只处理对应故障，不重置所有硬件设置。

## 3. AUX：让 SIGNAL 有一个来源

将 AUX 定义为外接接收机遥测。SIGNAL 表示这条辅助通道的接收强度，与真实网络质量、玩家思考进度、答案正确性无关。

连接时沿用已有三处模拟电台、调谐与增益控制。AUTO 提供电台活动包络，MAN 使用当前调谐值。两种模式都必须经过 AUX 是否连接这一条件。

拔出后，指针在约 250–400 ms 内回落到低位，停止大幅自动摆动；可保留极低的本机底噪。调谐和增益旋钮保留位置，转动仍有机械反馈，但没有外部台可供接收。背面即时提示“AUX 已断开 · SIGNAL 无外部输入”。

插回后，约 150–250 ms 恢复到当前调谐、增益和 AUTO / MAN 状态决定的位置。无需扫满刻度，也不重置旋钮。

暂不让 AUX 接管示波器输入。现有实体短接线已经明确表达本地校准来源，强行切换会让 FREQ、WAVE 和 LOCK 的含义变得模糊。未来若要观察外接信号，需要完整设计信号源选择及接线路径，不隐藏在拔插彩蛋里。

## 反馈必须在背面先成立

玩家拔插时看不到正面，因此每次操作必须同时具备：

1. **立即的手感反馈**：插头脱离或就位，线缆随动，声音开启时有接触声。
2. **背面的状态依据**：网口灯、供电指示灯，以及已有状态提示中的一句具体结果。
3. **持续的正面结果**：翻回去后仍能看到离线画面、归零指针或断电状态。

不自动翻转机器，不增加常驻正面小窗，也不把已发生的故障动画在翻面后重新播放。供电切换这类短暂事件，可在既有状态提示中保留最后一次结果，直到下一次操作。

拔插沿用现有点击动作和键盘等价操作，不新增一套必须掌握的手势。鼠标悬停或获得焦点时可说明后果，如“拔出网线 · 终端将脱机”，操作无需确认弹窗。

## 既有 TEST 与声音开关

LAMP TEST 保持灯光检查的单一职责，可扩展为背面测试灯和前面 NETWORK / LOCK 等指示灯的短暂测试覆盖；结束后恢复真实状态。不要在灯光测试中转动机械计分旗或显示“联网成功”。

实施时工作区已采用独立 MUSIC 与 SFX 开关；本次保留这项更新。无供电时音乐和持续电声停止，偏好保留，关机放电及机械操作仍遵守 SFX 开关。AUX 不兼任声音总线，拔 AUX 不应关闭背景音乐或按键声。

## 状态与冲突规则

实现时先统一计算硬件结果，再让所有表现消费同一结果：

```text
supply = DC 已连接 ? external : 四节电池齐全 ? battery : none
powered = 总开关 ON 且 supply != none
terminalOnline = powered 且 RJ45 已连接 且真实连接可用
auxAvailable = powered 且 AUX 已连接
scopeAvailable = powered
```

优先级：无供电 → 终端脱机 → AUX 无输入。主屏只展示当前最高优先级的阻塞及恢复方法；低优先级情况保留在各自接口提示里。恢复供电不能顺便把网线、AUX 或总开关改回默认值。

`powerOn` 保留为开关位置；`consoleHardware()` 统一推导实际供电、通信与 AUX 状态。所有屏幕、仪表、读盘、音乐、打印与无障碍文字采用同一 `powered`；游戏提交采用同一 `online`，避免画面关了但快捷键仍能提交。

角色、回合或房间变化时，即使终端脱机或失电，也立刻撤销旧密钥的可见权限和残影。后台状态持续接收不意味着旧秘密可以继续显示。

恢复动作只恢复连接与展示，不产生游戏指令。正在走纸或读盘时失电需暂停电动部分；人工拖动及弹出机构仍按机械规则工作。复电后按当前盘位、权限和纸带状态继续，避免重复出纸或重新发放旧盘。

首次进入默认完整接线。拔线、取电池等探索状态只保留在当前页面，不跨刷新、跨新房间持久化。主题、语言及声音偏好仍按现有规则保存。

## 小屏与减少动态效果

移动端及 WebGL 回退不要求玩家翻到不可用的背面去排障。主屏/状态提示提供同样的条件恢复入口，明确当前供电与连接状态。

减少动态效果时，线缆、指针和画面直接到达目标状态；所有文字反馈、权限检查和恢复方式保持完整。状态不能仅靠声音、颜色或闪烁表达。

## 落地顺序与验收

先实现 DC + 电池 + 总开关的统一供电，再实现 AUX + SIGNAL。两者能立即让原有部件形成清楚关系。最后接入 RJ45 的终端脱机与恢复，确保提交、过期草稿和多人对局状态处理完整。

验收围绕真实因果，而非新增点击数量：

- DC 拔出且电池齐全，机器继续运行；随后取出任一电池，整机失电。
- DC 接通时移除任意电池不关机；总开关 OFF 时接回 DC 不开机。
- 拔网线只隔离本终端，其他玩家继续；示波器仍正常工作。
- 拔 AUX 时 SIGNAL 回落，主屏、NETWORK、本地示波器保持各自状态。
- 插回网线面对真实断网时不假亮“已连接”；面对已推进回合时不提交旧草稿。
- 所有故障均能从当前可见界面恢复，静音、键盘、减少动态和小屏条件下同样成立。
- 玩一整局不触碰背面，正常流程不增加任何步骤。

## 已核对的现有实现

- `Console.tsx`：接口、电池、开关、测试灯的动作分发；现有背面回合提醒与电源提示。
- `model.ts`：本地硬件状态、软盘权限与动作、SIGNAL 模拟台及 AUTO 活动包络。
- `engine.ts`：插头与线缆变形、供电表现、示波器本地回路和测试灯。
- `paint.ts`：可交互目标、主屏与状态文本、NETWORK 状态来源。
- `assets/console/README.md`、`.impeccable.md`：设备命名、本地校准回路和设计背景。
- `/preview`：实际正背面布局；背面现有 LINK / RJ45、AUX / SERIAL、DC、电池仓、音频开关与 LAMP TEST。
