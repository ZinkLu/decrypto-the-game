## 已确认的显示问题

### F01 · P2 · 对方解码被称作“队友正在解码”

房间 `6386` 第二轮，我是 A 队；B 队 Morozov 加密，Lebedev 解码。左侧名册明确将 B 队标为解码中，中央 CRT 却显示“队友正在解码”。桌面截图：[05-opponent-decrypt-wrong-team.png](./05-opponent-decrypt-wrong-team.png)。对应 DOM：[opponent-decrypt-dom.txt](./opponent-decrypt-dom.txt)。

原因：`web/src/components/console/paint.ts:424` 等待分支按 phase 固定写“队友正在解码”，未根据当前玩家与行动方的关系选择文案。建议用 actingTeam / myTeam 区分“我方/对方正在解码”，并显示具体行动人；手机等待页也应明确当前行动方。

### F02 · P2 · 降级通知覆盖后续进度和操作说明

第二轮第一条 AI 线索超时并降级后，AI 仍继续请求第二条线索，CRT 底部一直显示“AI 未能完成回答，已使用备用线索或合法猜测继续。”，原本的已完成计数消失。刷新后仍复现。截图：[03-ai-fallback-wait.png](./03-ai-fallback-wait.png)。

原因：`web/src/components/console/paint.ts:464` 用 `status || foot` 占用同一行；`internal/game/ai.go` 将本轮降级通知保留。建议保留独立的实时任务进度，同时用单独一行或可展开状态显示“第 1 条已降级”。不要让通知取代当前仍需要的操作说明。

### F03 · P2 · 窄桌面关键辅助文字过小

866×863 仍走 3D 桌面界面，整机缩小后，CRT 底部异常提示、首轮线索输入、名册行动状态明显难读；周围仍有较多上下留白。1280×800 可读性改善，高画质不能根本解决文字随整机缩小的问题。截图：[04-narrow-desktop-readability.png](./04-narrow-desktop-readability.png)、[01-ai-wait-desktop.png](./01-ai-wait-desktop.png)。

原因：`web/src/index.css:414` 的移动端断点为 850px；`paint.ts` 在纹理中使用 21px 状态文字，再随整机投影缩小。建议按有效屏幕/内容宽度切换便携界面，或提供可放大的任务区；错误和输入文字应有屏幕像素级最小字号。此项是本次目视可读性判断，未声称测得 WCAG 合规性。

### F04 · P3 · AI 猜码进度没有归属实际玩家

首轮实际由 Whitfield 解码，CRT 底部显示“AI Agent · 已完成 …”，名册对应行只有“解码中”，没有相应完成计数。截图：[01-ai-wait-desktop.png](./01-ai-wait-desktop.png)。

原因：`internal/game/ai.go:112–122` 使用字面量 `AI Agent`；`web/src/components/console/model.ts:375` 仅在上报名称与名册姓名唯一匹配时显示进度。建议发送明确的玩家 ID 或队伍动作 ID；多人共同猜码时显示队伍进度，不将通用标签误当玩家。

### F05 · P2 · 手机回执缺少直接可核对的公开密码

房间 `3291` 第三轮，手机提交 `1,4,2` 后回执显示“拦截失败 · 解码失败”，但没有展示正确密码；打开密报记录才看到 `3,4,1`。桌面第四轮回执则直接展示三位公开密码和对应线索。

终局也复现同样差异：桌面显示最后密码 2–4–3，手机只显示胜方和成败，需另开历史；见 [手机终局](./11-game-over-mobile.png)。

原因：`web/src/components/console/MobileConsole.tsx:91–116` 的回执分支只输出成败，没有像桌面 `paint.ts:408–420` 一样读取已公开历史。建议两端都在结算展示公开密码、我方提交及行动方。手机还出现“拦截失败 ·”的孤立分隔符，且未说明是对手拦截失败；见 [07-mobile-decrypt.png](./07-mobile-decrypt.png)。
