# 画质与性能

画质是页面右上角“设置”里的一项：自动 / 高 / 中 / 低。它属于这次会话的页面设置，不是机器上的零件。本文说明每一档关掉什么、自动档怎样选、机器闲着时怎样省电。代码在 `web/src/console/quality.ts` 和 `engine.ts`（`applyQuality`、帧循环的节奏）。

## 档位

每一档是 `qualityProfiles` 里的一行。引擎应用的、设置里悬停提示显示的，都是这同一张表，所以提示不会和实际行为不一致。切换立即生效，不重新载入。

| 开关 | 高 | 中 | 低 | 含义 |
| --- | --- | --- | --- | --- |
| `pixelRatio` | 2 | 1.5 | 1 | 设备像素比的上限 |
| `areaLights` | 开 | 关 | 关 | 两盏大面积的影棚灯（`RectAreaLight`） |
| `shadows` | 开 | 开 | 关 | 主光的阴影（PCF，1024 贴图） |
| `screenGlass` | 开 | 开 | 关 | 六块显像管前的物理玻璃 |
| `nixieCover` | 开 | 开 | 关 | 辉光管的亚克力罩和管壳玻璃 |
| `crtOptics` | `full` | `full` | `lite` | 显像管的光学效果 |
| `ambientFps` | 60 | 30 | 30 | 有人操作时氛围动画的帧率 |
| `backdropBlur` | 开 | 开 | 关 | 纸带阅读器背后的 CSS 模糊 |

高档是完整的机器，往下每一档只减不增。

几点说明：

- **关掉面光源后**，主光、补光和天光的强度乘以 1.26，整体曝光不变。看得出的差别是投影的边缘略硬。
- **`lite` 光学**把画面直接印在面板上：不计算穿过玻璃的折射，没有光晕采样，没有色散。扫描线、滚动带、闪烁和颗粒保留。显像管上的输入框要跟着画面走，所以 `engine.bounds()` 把同一个选择传给 `crtDisplayUv`，两种光学下输入框都对得上字。
- **画质不改变交互动画。** 任何一档都不缩短、不省略玩家触发的动作。它和系统的“减少动态效果”设置互不相关。

每一档都保留的：

- **环境反射。** 去掉它，金属就失去质感；其他低档开关都关掉之后，再去掉它也省不了多少。
- **MSAA。** 抗锯齿在创建 WebGL 上下文时确定，之后无法切换。

窄屏布局用紧凑终端代替 3D 舞台，那里不显示画质选择。舞台没有尺寸时引擎不渲染。WebGL 启动失败时也不显示。

## 自动档

自动档实际测量，不看硬件型号。

1. 模型载入后，引擎先渲染 8 帧，让着色器编译完成、管线稳定。
2. 接着连续渲染四分之一秒，帧与帧之间不等显示器刷新。每帧渲染后读回一个像素，迫使 GPU 把这一帧做完，测到的时间才包含 GPU 的部分。
3. 取后一半样本的中位数作为单帧耗时。只看后一半是因为空闲的 GPU 会降频，刚开始的几帧偏慢。
4. 单帧不超过 13 ms（`frameBudget`）就留在当前档位。13 ms 给合成器和页面的其余工作留出了 16.7 ms 里剩下的部分。
5. 超过时降档：高档测得不超过 36.4 ms（13 × 2.8）降到中，否则直接降到低；中档超过就降到低。2.8 是实测的高、中两档 GPU 耗时之比。降档后再测一次，直到合格或到达低档。

自动档只会往下走，不会因为某一帧快就往上试。结果存在 `decrypto-quality-auto`，下次访问从这一档开始，不必每次都从高档重来。再点一次“自动”会从高档重新测量。

## 氛围帧与闲置

引擎把帧分成两类：

- **有变化的帧**：玩家改了什么，或者零件、显像管、纸带还在动。这类帧立即渲染，每次显示刷新一帧。
- **氛围帧**：只有扫描线、示波器光点和仪表指针在动。这类帧按节奏渲染。

氛围帧的帧率由 `ambientRate()` 决定：

| 情况 | 帧率上限 |
| --- | --- |
| 有人在操作 | 该档位的 `ambientFps` |
| 10 秒没有指针、键盘或滚轮输入 | 30 |
| 窗口失去焦点 | 20 |

上限和档位自己的帧率取较小者。20 帧是示波器模拟的步长，再低光点就不连贯。下一次输入立即恢复档位的帧率。

少画的帧不会丢信息：示波器在下一次渲染时补算自上次显示以来的全部时间，被跳过的指针动作记为欠账，下一帧画出它的当前位置。

机器断电或系统要求减少动态效果时，没有氛围帧。

### 循环会睡眠

一次 `tick` 如果什么都没画、也没有东西在动，就不再请求下一次显示刷新。它设一个定时器，在下一个氛围帧、指示灯超时或最多 500 ms 之后醒来。任何输入事件和引擎的每个公开方法都会立刻唤醒循环。页面隐藏时不渲染。

## 实测

以下数字是在一台 Apple M4 Max 上测的，场景是对局后期的整机（`?preview=late-game`）。它们说明各项开销的相对大小，换一台机器数值会不同。

### 每个开关单独关掉能省多少

在 2880×1800 下逐个关闭，对照每帧 5.9 ms 的同步渲染。斜杠前是 GPU 上省下的比例，斜杠后是软件光栅化（1440×900）下的比例。

| 开关 | 节省（GPU / 软件光栅化） |
| --- | --- |
| `pixelRatio` 降到 1.5 | 34% |
| `pixelRatio` 降到 1 | 51% |
| `areaLights` | 46% / 28% |
| `shadows` | 20% / 13%，另加每次阴影贴图刷新（189 次绘制调用，49.2 万三角形） |
| `screenGlass` | 22% / 10% |
| `nixieCover` | 15% / 8% |
| `crtOptics` 改为 `lite` | 最多 15% / 12% |
| `ambientFps` 减半 | 稳态负载减半 |
| `backdropBlur` | 未测 |

各项互相重叠，不能相加。整档的单帧耗时：高 5.2 ms，中 2.6 ms，低 1.8 ms。整机约 64.5 万个三角形，几何量不是瓶颈。

### 闲置的开销

2026-09-23 测量，窗口在 5K 显示器上（画布 5120×2600，高档）。“之前”指加入闲置降速和循环睡眠之前。

| 状态 | 之前 | 之后 |
| --- | --- | --- |
| 正在操作 | 60 帧，GPU 占用 39%，CPU 0.86 W | 不变 |
| 闲置 10 秒 | 60 帧，GPU 占用 36%，CPU 0.77 W | 30 帧，17%，0.26 W |
| 窗口在后台 | 60 帧，GPU 占用 35%，CPU 0.79 W | 20 帧，12%，0.16 W |
| 机器断电 | 每秒唤醒 175 次，主线程 2.1% | 每秒唤醒 58 次，0.1% |

在这个尺寸下，每一帧哪怕只画一个像素也要花约 2.3 ms 的 GPU 时间，用在清除、解析和合成多重采样的 5K 缓冲上。所以少画一帧比只重画一部分省得多：把氛围帧裁剪到几块屏幕的范围内，只省了大约五分之一。

## 重画的开销

`paint()` 每次都画出全部表面，开销主要在主线程。有三处专门处理：

- **倒计时钟单独画。** 倒计时每秒变一次，其他表面不变。`paintClock()` 只画这一张 520×218 的贴图。见[代码组织](code.md)里关于 `paintKey` 的说明。
- **上传前先比较哈希。** `paint()` 总是返回新的 canvas，引擎对每张算一个哈希，像素没变就不上传。最长的纸带贴图上传最贵，它大多数时候不变。
- **哈希一次读回。** 从 canvas 读像素要等 GPU，逐张读很慢。引擎把一次重画的所有 canvas 缩成 32×32，拼进一张图集，只读回一次。缩小时按整格取平均，小字的变化也会反映在哈希里。61 个表面逐张读要 26 ms，合在一起读要 6 ms。

合起来，倒计时走一秒占用的主线程时间从 31 ms（最高 48 ms）降到 8 ms。

阴影贴图不自动更新（`shadowMap.autoUpdate = false`），只在零件移动的那些帧刷新。不停摆动的指针和旋钮指示线太小，在阴影贴图里看不出来，所以不投影，静止的阴影就不必跟着重算。

## 开发时查看

开发服务器上，渲染画布的 `data-` 属性每 750 ms 更新一次：

| 属性 | 内容 |
| --- | --- |
| `data-scope-fps` | 实际渲染的帧率 |
| `data-draw-calls` | 绘制调用数 |
| `data-triangles` | 三角形数 |
| `data-ambient-pace` | 当前氛围帧率上限 |
| `data-face` | `front` 或 `rear` |

加上 `?quality=high|medium|low|auto` 可以为一次截图或测量固定档位，不改动保存的选择。见[开发预览](preview.md)。
